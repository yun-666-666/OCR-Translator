# Task summary

Completed big optimization #13: translation terminal-state integrity.

After the existing one-time truncation repair, translation now validates the
final Chat Completions or Responses terminal metadata before parsing and
returning text. Explicitly truncated, incomplete, content-filtered, failed, or
otherwise non-successful responses can no longer be displayed and cached as
successful translations.

Responses streaming now also recognizes `response.failed`, preserves structured
error metadata, infers a missing failed status from the event type, and retains
the upstream reason even when no text was emitted. API keys are sanitized from
the surfaced failure detail.
