## Important decisions made

- Cache identity now includes profile ID, normalized base URL, model, normalized wire API, normalized reasoning effort, custom prompt, line-break mode, and context.
- API keys remain excluded from all cache and in-flight keys. Credential rotation does not change translation semantics, and secrets must not be persisted.
- Persistence uses one daemon timer per dirty window. Repeated stores reuse the scheduled timer.
- JSON serialization and file I/O happen outside the main cache lock and are serialized by a dedicated persistence lock.
- Generation numbers prevent an older timer snapshot from overwriting a newer flush or clear.
- `.tmp` plus `os.replace()` remains the atomic-write mechanism.
- The default persistence delay is 0.25 seconds. Normal translation completion updates memory and returns without waiting for disk.
- `close()` cancels the pending timer and flushes synchronously.
- A store racing after close writes synchronously because no timer can be scheduled at that lifecycle point.
- Cache schema version 2 intentionally ignores legacy entries. The old file in this checkout contained translations produced before the response-decoding and identity fixes, so reusing it was not safe.
- `clear_all()` and `clear_provider()` persist synchronously so a delayed write cannot resurrect removed entries.
- Git uses the existing global identity, branch `main`, and local `core.autocrlf=false` to preserve the checkout's existing line endings.
- The historical source contains substantial trailing whitespace. It was preserved in the baseline rather than creating an unrelated mass-formatting diff.
