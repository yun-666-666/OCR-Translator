# Handoff: UI checkbox for translation_failover_enabled

**Date:** 2026-07-18  
**Branch:** `codex/remove-hidden-legacy-controls-20260716`  
**Baseline:** `16812b9`  
**Rollback branch (untouched):** `codex/backup-before-failover-profile-optin-20260718`  
**Backup:** `.codex/backups/2026-07-18_17-59-59/`

## Problem

Commit `16812b9` introduced `translation_failover_enabled` (default false for non-active profiles) and correctly gated failover/race eligibility on it. The Custom AI profile editor had no control for the field, so ordinary multi-profile failover was unusable after migration unless users edited JSON.

## Changes

### `gui_settings_builder.py`
- Added `ai_profile_translation_failover_var` (`BooleanVar`, default `False`).
- `load_profile` loads `translation_failover_enabled` from the selected profile (missing/legacy → false) and clears it on new/empty form.
- Added one labelled checkbox in the existing AI Model Profiles editor:
  - Label key: `ai_profile_translation_failover_label`
  - English fallback: `Allow as translation failover`
- Button column rowspan extended to include the new row.

### `gui_profile_controls.py`
- `build_custom_ai_profile_values_from_form` always emits `translation_failover_enabled`.
- Reads checkbox when present; defaults to `False` when absent.
- Value flows through existing `save_profile_form` → `add_profile` / `update_profile`.

### `tests/test_custom_ai.py`
- Form-value seam tests for checkbox true/false/absent.
- Source wiring assertion for the settings builder checkbox.
- Profile manager persistence test through the form-value path.

## O2 preserved

- Active translation profile remains eligible regardless of the checkbox.
- Other enabled profiles participate in failover/race only when `translation_failover_enabled` is true.
