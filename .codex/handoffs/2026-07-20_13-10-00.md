## Important decisions

- Cache-hit response handling must enter the UI thread before it can advance display/translation sequence state or reach Tk-backed display behavior.
- This adds at most one UI event-loop tick for cached API OCR responses; it aligns cache-hit behavior with async provider completion and removes the worker-thread UI/state path.
- Updated the two existing cache-hit tests to execute their queued callback deliberately.  Added an assertion that `last_displayed_batch_sequence` remains unchanged when `run_api_ocr` returns.
- Existing user changes in `handlers/translation_requests.py`, `tests/test_custom_ai.py`, and the earlier `worker_threads.py` re-export lines were preserved.  The final shared diff therefore includes those pre-existing changes as well as this focused change.
