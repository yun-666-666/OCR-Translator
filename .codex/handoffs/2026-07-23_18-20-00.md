# Handoff — Route-scoped temporary non-stream bypass (2026-07-23)

## Task summary

Added a **route-scoped, short-lived, recoverable** non-stream bypass for Custom AI stream transport instability. This does **not** change OCR, translation overflow scheduler, UI, or model parameters.

Live motivation (Run B):
- 3× `custom_ai stream translation failed transiently; retrying non-stream request`
- `Connection aborted` / `ConnectionResetError(10054)`
- Many workers stretched to 5–10s because each request first failed stream, then retried non-stream

## Behavior

### Trigger (transport only)
Only these stream failures count toward the streak:
- ConnectionReset / connection aborted
- SSL EOF/reset
- read/connect timeout / chunked encoding transport failures

Explicitly **not** counted:
- 401/403/404
- 429 / rate limit
- model/content parse errors
- empty stream content fallback (existing path remains separate)

### Enter bypass
- First stream transport failure: keep existing **same-request** non-stream retry; streak = 1
- Second consecutive stream transport failure on the **same route**: open temporary bypass
  - `STREAM_TRANSPORT_BYPASS_ENTER_STREAK = 2`
  - `STREAM_TRANSPORT_BYPASS_TTL_SECONDS = 30.0`

### While bypass active
- Future translation requests on that route go **directly non-stream**
- Avoids “stream fail → non-stream retry” double tail latency
- Other routes/profiles remain unaffected

### Recover
- One successful request that used the bypass recovers immediately
- Or bypass expires after 30s TTL
- Same-request non-stream recovery after stream transport failure does **not** clear the streak / cancel a just-opened bypass

### Metrics / logs (content-free)
Counters on provider:
- `stream_transport_failure_streak_max`
- `stream_transport_bypass_entered`
- `stream_transport_bypass_requests`
- `stream_transport_bypass_recovered`
- `stream_transport_bypass_expired`

Logs:
- `LATENCY: stream transport failure streak ...`
- `LATENCY: stream transport bypass entered ...`
- `LATENCY: stream transport bypass active; using non-stream ...`
- `LATENCY: stream transport bypass recovered ...`
- `LATENCY: stream transport bypass expired ...`

## Why this only mitigates transport tail latency
Provider connectivity can still be bad. This change only prevents repeatedly paying for a doomed stream attempt after the route has just proven stream transport is unstable. It is not a claim that xAI/network is healthy.
