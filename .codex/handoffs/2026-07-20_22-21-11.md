# API OCR keep_linebreaks snapshot freeze

## Task summary

Fixed the API OCR path so a captured frame's `CaptureUISnapshot.keep_linebreaks` is frozen once and used for both:

1. OCR frame-cache mode identity (`_get_api_ocr_cache_mode_key`)
2. provider request parameters (`process_api_ocr_async` → `perform_ocr` → `recognize`)

Previously both sites live-read `keep_linebreaks_var`, so an already-captured frame could change cache identity and OCR formatting after the user toggled keep-linebreaks. Local OCR already used the frame snapshot; API OCR now matches that contract.

## Important decisions

- `run_api_ocr` freezes `keep_linebreaks` from `capture_snapshot` when present.
- That frozen value is passed into `_get_api_ocr_cache_mode_key(..., keep_linebreaks=...)` and into `process_api_ocr_async` / `perform_ocr`.
- Explicit `keep_linebreaks` on `_get_api_ocr_cache_mode_key` and `perform_ocr` suppresses live Tk variable reads.
- Compatibility callers without a snapshot still freeze the current live var when it exists, so cache key and provider request stay consistent for one in-flight call (closes the same-request TOCTOU).
- Compatibility callers with no snapshot and no `keep_linebreaks_var` leave `keep_linebreaks=None`, preserving the historical mode-key shape (`api` without a keep_linebreaks segment) used by older cache-hit tests and cache entries.
- Pre-existing uncommitted work was preserved:
  - 429 / cooldown classification changes already in `handlers/translation_requests.py` and `tests/test_custom_ai.py`
  - API OCR cache-hit UI scheduling in `worker_threads.py` / tests
  - Local OCR UI-thread routing in `worker_ocr.py` / tests / `tests/test_paddle_ocr_backend.py`
