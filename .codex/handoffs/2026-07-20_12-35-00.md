# PaddleOCR startup and translation cooldown recovery

## Task summary

Optimized the two bottlenecks confirmed in the 2026-07-20 runtime log:

1. Restored the missing PaddleOCR settings/cache-key re-exports from
   `worker_threads`, allowing the existing background prewarm path to start
   instead of being skipped at application startup.
2. Refined Custom AI translation failure classification so connection resets
   and read timeouts retry on short exponential cooldowns, while true provider
   rate limits retain their dedicated `Retry-After` cooldown without a second,
   longer profile-unavailable cooldown being added on top.

## Important decisions

- `get_paddleocr_settings_from_app` and
  `get_paddleocr_ocr_cache_mode_key` are re-exported from `worker_capture` by
  `worker_threads`, preserving the existing import contract used by startup,
  preview, and worker paths after the module split.
- Explicit HTTP 429/rate-limit errors do not receive an additional
  profile-unavailable cooldown. The transport layer remains the sole owner of
  the real rate-limit cooldown and honours `Retry-After`.
- TLS/connection-reset failures start at 2 seconds and read/connect timeouts at
  5 seconds; both retain exponential backoff. HTTP 502/503/504 remains at the
  existing 15-second initial cooldown.
