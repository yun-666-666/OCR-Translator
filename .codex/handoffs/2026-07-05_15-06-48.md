# Task summary

Implemented OCR stability/quality gating before local Tesseract OCR text is
submitted for translation. Suspicious short or noisy OCR candidates are held for
a very short confirmation window, can be replaced by a more complete candidate,
and flush after the maximum wait so subtitles do not remain pending forever.

The final submitted OCR text still flows through `start_async_translation()`, so
instant cache display, active/in-flight de-duplication, provider cooldown, and
translation context updates keep their existing identity rules. API OCR sequence
handling was left unchanged.

# Important decisions

- Added `OcrStabilityGate` in `worker_threads.py` with centralized timing
  constants: 120 ms minimum confirmation and 250 ms maximum wait.
- Clear-looking OCR text submits immediately; suspicious short/noisy candidates
  wait briefly for another OCR frame.
- A clearly more complete OCR result replaces an older pending candidate and is
  the only text submitted to translation.
- Pending gate state is cleared when source context changes, OCR output becomes
  empty/placeholder, the OCR thread stops, cache is cleared, translation starts
  or stops, and the OCR model changes.
- Local OCR final submission still calls the existing `start_async_translation()`
  path, preserving instant cache, near-duplicate skip, in-flight de-duplication,
  provider cooldown, and Custom AI context behavior.
