# Task summary

Implemented lightweight automatic capture backend selection for OCR screenshot
capture. When `capture_backend` is `auto` or an unknown legacy value, the app now
benchmarks `mss` and `pyautogui` on a small source-region sample, excludes
failing or invalid backends, caches the fastest available backend, and rechecks
when source geometry changes subject to throttling.

Explicit `mss` and `pyautogui` settings are still respected. If a requested
backend fails during capture, `capture_screen_region()` can fall back to the
other backend so the translation loop keeps running, and the selector records
the fallback for future auto captures.

# Important decisions

- Added `CaptureBackendSelector` in `ocr_utils.py` with a default sample count
  of 2 and a 10 second minimum recheck throttle.
- Benchmarks capture only the current source origin with width and height capped
  to a small safe region.
- Benchmark calls disable backend fallback so a failing backend is excluded
  instead of being credited for the fallback backend's success.
- `worker_threads.py` resolves `auto` through the selector, uses the actual
  backend in capture signatures, and keeps explicit backend choices unchanged.
- Unknown legacy backend config values are normalized to `auto` for selector
  resolution.
- `app_logic.py` initializes one selector per app instance.
- Logs include tested backend, sample count, median/average duration, selected
  backend, throttling, and fallback reason without secrets or user profile data.
