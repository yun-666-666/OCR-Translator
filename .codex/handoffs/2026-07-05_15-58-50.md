# Task summary

Implemented structured Custom AI translation output for OpenAI-compatible
translation endpoints. Translation profiles now carry a structured output mode:
`off`, `auto`, or `strict`, defaulting to `auto`.

For Chat Completions requests, `auto` and `strict` add a JSON schema
`response_format` requiring `{ "translation": "..." }`. For Responses API
requests, the same schema is converted to `text.format`. Successful structured
responses are parsed from the `translation` field only, so the JSON wrapper is
not displayed to users.

`auto` mode detects 400/422 structured-output incompatibility, remembers it per
wire API + canonical endpoint + model, retries once with the existing plain text
contract, and stores/cache-keys the degraded result under the plain text
contract. `strict` mode does not degrade and returns a clear structured output
error. Streaming in `auto` keeps the existing plain text streaming behavior.

# Important decisions

- Kept the setting profile-scoped instead of adding a global setting, so
  endpoint-specific compatibility can be controlled and remembered cleanly.
- Used request contract identity (`json_schema` or `text`) in Custom AI cache
  params and in-flight keys rather than only the user-facing mode.
- In `auto`, stream mode keeps plain text output to preserve real-time partial
  display.
- Race mode includes structured output mode in semantic equivalence and stores
  winner results only under equivalent structured-output contracts.
- Existing output-limit unsupported fallback remains intact and can stack with
  structured-output fallback.
- Error sanitization continues through the existing API key redaction paths.
