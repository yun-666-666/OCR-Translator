# Log-driven freshness and local OCR optimization handoff

## Task summary

Implemented the highest-priority optimizations identified from the latest meaningful runtime session (`PaddleOCR + luna`, 2026-07-16 00:39:22–00:42:40):

- Stop sequential Custom AI failover after a newer translation sequence has already reached the display.
- Replace the fixed 1.5-second bounded-overflow decision with a conservative route-history threshold carried by the immutable request snapshot.
- Record real local PaddleOCR duration and pace capture from recent local p50 instead of relying only on API in-flight counts.
- Preserve all existing UI, configuration schema, exact-frame cache, API OCR behavior, race-mode exclusion, and maximum two-call overflow bound.

The implementation was done on branch `codex/log-driven-freshness-20260716`, based on `4c7c014`, and was not pushed, merged, or published.

## Files changed or created

### Production

- `handlers/translation_requests.py`
  - Adds display-sequence freshness checks around sequential failover.
  - Exposes route latency history in all request snapshots, including configured `safe` mode.
- `worker_translation.py`
  - Computes overflow age as `max(configured, min(4.0, route_p90 * 0.5))` after at least 8 route samples.
  - Falls back to the prior configured/default threshold for missing or malformed data.
- `worker_threads.py`
  - Passes the immutable snapshot into overflow scheduling.
  - Records `local_ocr_duration` only after real local OCR work, not cache hits or API OCR.
- `app_capture_ocr.py`
  - Uses local OCR p50 plus a 25ms scheduling margin, rounded to 25ms and clamped to `[base, 2 * base]`, after at least 8 samples.
  - Restores the API baseline before applying API normal/moderate/overloaded state after a model switch.

## Important decisions

- Freshness is based on `last_displayed_translation_sequence`, not merely the newest started request, so an older request remains a useful fallback until a newer result actually displays.
- Route scheduling uses route history from the timeout advisor because it remains populated in configured `safe` mode; adaptive-mode decision fields retain their original meaning.
- Route-aware overflow never lowers the configured/default threshold, never exceeds 4 seconds from route history, never applies to race mode, and never permits more than the existing two active calls.
- Local pacing applies only to the explicit PaddleOCR route. Unknown/future API routes are not treated as local.
- No perceptual frame matching was added because correctness risk remains higher than the measured benefit.
- The pre-existing untracked `.codex/release-artifacts/release-notes-v3.10.3-2026-07-15.md` was not edited or staged.
