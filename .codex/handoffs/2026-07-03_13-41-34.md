# Balanced translation latency and quality optimization handoff

## Task summary

Completed a balanced translation optimization pass:

- added a user-adjustable Custom AI minimum submission interval in Settings
- changed the default short-subtitle interval from the hidden 1.0-second floor to
  an explicit 300 ms setting
- preserved length-based protection for long OCR payloads, provider cooldowns,
  single-flight execution, and latest-pending-subtitle replacement
- added sanitized queue/worker/total timing summaries
- upgraded Custom AI context from source-only strings to accepted
  source/translation pairs for better terminology, tone, and character consistency

## Important decisions

- The UI setting is `AI translation minimum interval (ms)` / `AI 翻译最小提交间隔（毫秒）`.
- Config key: `custom_ai_submit_interval_ms`.
- Default: 300 ms; accepted UI/runtime range: 0–5000 ms; UI increment: 50 ms.
- Long inputs add up to three seconds on top of the user-selected base.
- Provider cooldown remains authoritative and Custom AI concurrency remains one.
- The timing metric contains only sequence and numeric durations; it does not add
  subtitle text, translation text, prompts, keys, or URLs.
- Context stores `(source_text, translated_text)` pairs. Legacy string-only context
  remains accepted defensively.
- Existing SQLite cache schema remains unchanged; paired context is already safely
  represented inside the existing serialized cache-parameter hash.
- Existing untracked `.codex/release-artifacts/` content was left untouched.
