# P13 review repair: block all legacy plaintext rewrite paths

## Task summary

Reviewed Grok's P13 fail-closed credential-store implementation. The add/update failure transaction was correct, but failed migration of an already-existing plaintext legacy profile still left one rewrite path: `_sanitize()` could request a normal save for unrelated default normalization, and later ordinary profile saves could serialize the in-memory legacy key again.

The repair blocks any write whose staged data contains a non-empty API key without a credential reference. Serialization itself also never emits an `api_key` field. This preserves the original legacy JSON byte-for-byte until a credential-store write succeeds, while keeping the existing runtime key available for the current process.
