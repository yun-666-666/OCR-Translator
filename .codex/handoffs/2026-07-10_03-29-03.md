## Implementation decisions

- Plan A keeps the first repeated local frame but drops every later exact
  duplicate until the capture signature changes. API OCR retains its existing
  immediate exact-duplicate suppression.
- Local translation-cache lookup now happens after the existing short-text
  stability admission. Clear candidates still proceed immediately; uncertain
  candidates wait for their existing debounce window before any cache query.
- xAI Chat translation requests use a stable `x-grok-conv-id` per translation
  configuration to improve automatic prompt-cache routing.
- Responses translation requests use a stable, privacy-safe
  `prompt_cache_key` per endpoint/model/profile. If a gateway explicitly
  rejects that field, the request retries once without it and that capability
  is remembered for the endpoint/model.
- The compatibility fallback loop now covers all four optional request fields:
  prompt cache key, reasoning effort, structured output, and output limit.
- xAI `cost_in_usd_ticks` is converted to `cost_usd` and recorded in the short
  translation log. Providers that do not return a cost continue to show zero
  rather than receiving an invented price.

## Log and cost analysis

- The latest short translation log contained 2,072,071 input tokens, with
  950,464 cached input tokens (45.87 percent by tokens), and 53,807 output
  tokens. Existing cost fields were all zero because the application had not
  parsed upstream cost ticks.
- The active translation and OCR configurations use different wire paths, so
  the implementation targets the wire protocol rather than treating xAI as the
  only provider. No keys, full URLs with credentials, or model credentials are
  recorded here.
