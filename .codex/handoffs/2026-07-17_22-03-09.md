# Task summary

Implemented one log-evidenced latency and spend reduction increment for the evening Custom AI session.

- Added a 0.75-second, scope-bound API OCR repeat backoff. After a valid remote OCR result repeats the already displayed subtitle, the same OCR route, language, image contract, and capture region does not encode or submit another remote image until the short deadline expires.
- Canonicalized official `api.x.ai` Chat Completions URLs to `/v1/chat/completions`, preventing the known invalid root-path fallback probe.

The backoff is intentionally conservative: it does not use fuzzy image hashes and therefore does not discard a potentially new subtitle. A changed route/configuration scope bypasses the old deadline immediately.

# Important decisions

- The repeat backoff starts only after the provider itself returns the same subtitle. It does not assume that visually similar frames have the same text.
- Cache hits remain immediate and bypass the backoff. Invalid/error/empty OCR results retain their existing behavior.
- The new endpoint special case is restricted to `api.x.ai`; generic OpenAI-compatible hosts retain their compatibility fallback candidates.
- No user profile/configuration file was edited and no real provider request was made.

# Remaining issues or next steps

- The remote OCR session also showed a high ratio of text repetitions caused by changing video pixels behind static subtitles. The conservative 0.75-second hold reduces immediate churn but does not perform semantic subtitle detection.
- A later, separately validated increment could use local PaddleOCR as a confidence-gated change detector before remote OCR, if the user wants a stronger cost reduction with an explicitly assessed latency/accuracy tradeoff.
- The xAI route still has externally observed TLS/read instability; this change removes the avoidable 404 path but does not alter the network route or provider behavior.
