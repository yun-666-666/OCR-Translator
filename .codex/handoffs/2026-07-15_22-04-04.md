# AI OCR cooldown fallback and 60-second wait repair

## Task summary

- Analyzed the newest `translator_debug.log` and Custom AI short log for the report that AI OCR translated once and then appeared to wait 60 seconds.
- Confirmed the immediate trigger was an HTTP 502 response carrying `Retry-After: 60`, not local PaddleOCR or capture latency.
- Fixed stale request-scoped cooldown state so a later successful in-flight response clears that cooldown while transport-wide 429 cooldowns remain protected.
- Scoped request/profile health to `ocr` or `translation`, so an OCR-side 5xx/configuration failure cannot pause translation when both roles use the same profile; genuine transport-wide 429 limits remain shared.
- Added locked request sequencing so an older concurrent success cannot erase a newer classified failure.
- Added classified Custom AI profile health durations instead of applying the same 60-second profile cooldown to every failure.
- Added automatic per-frame PaddleOCR fallback while the selected Custom AI OCR profile is cooling down. The saved OCR selection is not changed, and Custom AI OCR resumes automatically after recovery.
- Limited Custom AI OCR to two concurrent calls without changing the generic limit for other API OCR providers.
- Prevented cooldown errors from overwriting the last useful subtitle while PaddleOCR is covering the outage.

## Log findings

- At approximately 21:25:38, Custom AI OCR quickly reached eight active calls.
- The first translation was displayed at approximately 21:25:41.
- One OCR request then received HTTP 502 with `Retry-After: 60`, activating a 60-second request-scoped cooldown.
- Other already in-flight requests returned HTTP 200, but the old success handler only reset backoff counters and did not clear the active request cooldown deadline.
- The OCR loop continued creating batches every roughly 200 ms. The run recorded 78 batches, 52 cooldown short-circuit errors, 13 stale results, and a maximum of eight concurrent OCR calls; cooldown errors could replace useful subtitle text.
- Translation failover also exposed external profile problems: HTTP 402 insufficient balance, HTTP 403 precharge failure, xAI timeouts/404, empty content, and upstream timeouts. These remain provider/account/configuration issues rather than local OCR latency.

## Important decisions

- Fallback is runtime-only and frame-local. It does not rewrite the user's selected OCR model or add a new UI setting.
- Custom AI OCR uses a provider-specific concurrency ceiling of two; other API OCR providers keep the configured generic ceiling.
- HTTP 401/402/403, balance/precharge, invalid model, and invalid endpoint failures use a 300-second profile health cooldown.
- HTTP 500/502/503/504, gateway, connection, and timeout failures use 15 seconds; empty or invalid content uses 10 seconds; unknown failures use 30 seconds.
- A successful request clears request-scoped cooldown state but deliberately preserves transport-wide rate-limit cooldowns.
- Request-scoped transport cooldowns and profile health are isolated by OCR/translation role; HTTP 429 remains credential/transport-wide.
- Profile health writes are sequence-ordered under the existing rate-limit lock so stale concurrent completions cannot overwrite newer state.
- No live API calls were made and no real user configuration was copied into the isolated worktree.
