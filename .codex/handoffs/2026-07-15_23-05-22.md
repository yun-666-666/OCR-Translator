## Important decisions

- Custom AI OCR remains capped at two concurrent requests; concurrency was not reduced to one.
- Other provider capacity continues to use the configured generic limit.
- The 200 ms user base scan setting remains unchanged. Saturation dynamically applies backpressure only when the effective OCR route is an API provider with no free slot.
- A saturated capture iteration sleeps for the current adaptive interval and then captures the newest screen; obsolete intermediate video frames are intentionally not created or queued.
- PaddleOCR does not use the API saturation guard.
- Custom AI cooldown fallback is evaluated before saturation, so PaddleOCR keeps receiving frames during provider cooldown.
- Zero capacity remains an explicit disabled state and sleeps instead of busy-looping; invalid or overflowing values fall back to one.
- No UI, config schema, perceptual-difference heuristic, queue redesign, provider call, push, or release was added.
