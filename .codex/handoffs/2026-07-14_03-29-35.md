## Tests and commands run

### RED/GREEN evidence

- A new runner test failed before the runner/CI existed; the real runner now executes discovery plus legacy root tests in a temporary child log directory. CI disables persisted credentials and limits token permissions to `contents: read`.
- Prompt write/replace failure tests reproduced early in-memory publication and direct writes. Shared `atomic_file_io.write_atomically` now controls temporary creation, flush, fsync, replacement, cleanup, and preserves the primary failure if cleanup also fails.
- Corrupt INI tests reproduced source loss for parser and UTF-8 decoding failures. The source is now byte-preserved in an atomically published sibling corrupt backup before default recovery; backup failure leaves the original untouched.

- Build tests reproduced shell-string commands and unguarded environment mutation. The helper now uses interpreter-bound argument arrays and refuses package changes unless explicitly allowed.
- Logging tests reproduced three no-op reset messages and no cooling-skip coalescing. Reset logs are transition-only and cooling skips are content-free coalesced events.

## Important decisions

- CI remains intentionally offline and least-privilege: no secrets, `persist-credentials: false`, and `permissions: contents: read`.
- The shared atomic writer never writes through a link, publishes only via same-directory `os.replace`, and does not let cleanup errors hide the original publish failure.
- A profile/config parse failure is treated as recoverable local corruption, not as permission to silently discard bytes.
- `compile_app.py` is a guarded developer helper, not a package manager: its normal path cannot uninstall or replace PyTorch.
- No UI redesign or unrequested dependency upgrade was introduced.
