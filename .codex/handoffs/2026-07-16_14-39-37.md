# Translation subtitle layout and centering handoff

## Task summary

Implemented the approved translation display behavior on isolated branch
\`codex/translation-display-layout-20260716\`:

- Added the default \`compact\` layout: Custom AI is instructed not to emit
  explicit line breaks, and the renderer collapses returned newlines and
  \`<br>\` markers to spaces. Qt still wraps naturally only when the overlay
  width is exhausted.
- Added \`preserve_source_lines\`: it retains the existing OCR/source line
  boundaries and asks Custom AI to return translated breaks as \`<br>\`.
- Added an independent horizontal-center setting. It updates HTML and
  \`QTextBlockFormat\` horizontal alignment only; it does not change geometry,
  margins, font metrics, or vertical placement.
- Applied the same compact/preserve policy and horizontal alignment to the
  supported Tk fallback path, including RTL rerendering after a resize.
- Migrated existing \`keep_linebreaks=True\` configurations to
  \`preserve_source_lines\`, and keeps the legacy key synchronized for existing
  OCR/translation callers.
- Replaced the old ambiguous line-break checkbox with a two-choice selector
  and localized the new controls in English, Chinese, and Polish.

## Important decisions

- Compact mode is enforced at both request and render boundaries, so a model
  returning a stray \`<br>\` cannot force an early second line.
- The renderer preserves \`QTextEdit.WidgetWidth\`; compact mode does not
  suppress legitimate width-based wrapping.
- Horizontal centering defaults to disabled to preserve prior left/right
  direction-aware behavior. When enabled it uses \`Qt.AlignHCenter\`, without a
  vertical alignment flag.
- A final read-only code review found the initial Tk fallback gap; a regression
  test and the fallback implementation were added before the final test run.
- The live \`ocr_translator_config.ini\` was deliberately not edited.
