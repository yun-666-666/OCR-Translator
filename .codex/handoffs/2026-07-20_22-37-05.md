# Translation inactivity clear uses guarded UI scheduler

## Candidate selection

Reviewed remaining live-path worker Tk / `root.after` sites after Round 1 (`001ca78`).

Candidates considered:

1. `_schedule_inactive_translation_clear` still used raw `app.root.after(0, ...)` without shutdown / `winfo_exists` / TclError guards that `_schedule_ui_callback` already provides. **Selected.**
2. Pending translation flush / profile refresh delayed `root.after` sites. Deferred: needs delay support on `_schedule_ui_callback` or careful generation/deadline interaction review.
3. OCR stability flush delayed `root.after`. Deferred: same delay-support concern.
4. Instant-cache Tk var read inside `start_async_translation`. Deferred: entrypoints are already UI-scheduled; not a worker-thread Tk leak today.
5. Translation-sequence counter TOCTOU. Deferred: medium risk, broader locking design.
6. Compatibility `run_api_ocr` live Tk fallbacks without snapshot. Deferred: production path always supplies snapshot; not a live-path regression.

Selection criteria met for item 1:

- High confidence static proof: raw `root.after` can still fire after close / destroyed root while other worker UI paths drop those callbacks.
- Low risk: delay is already 0; swap to existing `_schedule_ui_callback` and clear the scheduled epoch on failure.
- <=4 files: only `worker_ocr.py` + tests + handoff.
- Deterministic tests without network.
- User-visible stability: avoids post-shutdown inactivity clear scheduling races.

## Task summary

`_schedule_inactive_translation_clear` now schedules `_apply_inactive_translation_clear` through `_schedule_ui_callback`. If scheduling fails (closing app, destroyed root, Tcl/runtime error), the scheduled epoch is cleared and the function returns `False`, matching the previous failure path without broad exception swallowing.
