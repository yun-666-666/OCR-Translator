# P13: No plaintext credential fallback on store failure

## Task summary

Credential store write/update failures for Custom AI profiles no longer fall back to writing plaintext API keys into profile JSON. Failures are atomic: no memory publish, no JSON replace, existing credential refs preserved, and callers get redacted errors.

## Changes

### `custom_ai_profiles.py`
- `_store_profile_api_key` raises `CredentialStoreError` on failure (no `_api_key_plaintext_fallback`)
- `serialize_for_disk` never emits plaintext when a credential ref exists; only preserves already-on-disk legacy plaintext when no ref is present
- `add_profile` / `update_profile` treat credential write failure as atomic transaction abort
- Migration of legacy plaintext only rewrites disk when the credential store accepts the secret
- Error messages include only safe profile ids / action text (no secrets)

### Tests
- Replaced plaintext-fallback expectation with no-fallback atomic failure coverage
- Added add/update credential-store failure tests for disk/memory/ref integrity and redacted errors
