# Task summary

Completed big optimization #14: monotonic translation-cache persistence.

Captured persistence operations can execute in a different order from their
cache generations. A successfully written newer SQLite delta can no longer be
overwritten by a later-arriving older delta. Stale success callbacks also no
longer mark an already finalized newer cache state dirty again.

The cache now tracks the highest successfully applied generation under the
SQLite lock, skips strictly older writes, and advances that watermark only
after success.

# Important decisions

- Protected the applied-generation watermark with the same lock as SQLite
  writes, making check-and-advance atomic with the commit.
- Initialized the watermark to `-1`, preserving generation-zero migration and
  startup-trimming writes.
- Skipped only strictly older generations; equal-generation idempotent writes
  remain safe.
- Did not advance the watermark on failure, so an older recovery write is still
  allowed when no newer state actually reached disk.
- Made success result handling idempotent for already-finalized generations.
- Left retry, close, clear, migration, and cache-recency behavior unchanged.
- Left the pre-existing untracked `.codex/release-artifacts/` untouched.
