# Race Profile Health and Semantics Handoff

## Task summary

Completed a sixth large translation speed and quality optimization.

Race mode previously grouped profiles by model string only. A low-reasoning or
different wire-API profile could therefore win a high-reasoning request, and its
result could be stored under the active profile's cache identity. The scheduler
also looked only at the active profile's cooldown, so one cooling relay could
delay healthy equivalents.

Race candidates now require the same normalized:

- model;
- wire API;
- reasoning effort, including the legacy `model_reasoning_effort` field.

Relay identity fields such as base URL, API key, profile ID, and name may differ.

Health behavior now:

- removes cooling candidates when at least one compatible candidate is healthy;
- keeps all compatible candidates when every one is cooling;
- reports the shortest compatible cooldown to the scheduler in race mode;
- preserves active-profile-only cooldown in non-race modes;
- calls the actual remaining candidate when health filtering leaves one healthy
  alternative.

This lets a healthy equivalent relay immediately replace a cooling active relay
without allowing a different reasoning/wire configuration to trade away
quality.

## Important decisions

- Required wire API equality because Responses and Chat profiles can carry
  different reasoning semantics even for the same model name.
- Required normalized reasoning equality so race winners remain safe to reuse
  under the active semantic cache request.
- Treated a failed cooldown lookup as healthy instead of silently removing a
  potentially usable endpoint.
- Kept all candidates when all are cooling so cooldown/error reporting remains
  deterministic.
- Avoided API keys in fallback candidate identity tuples.
- `.codex/release-artifacts/` remains untouched and excluded.

## Remaining issues or next steps

- Race still starts every healthy compatible candidate concurrently; future

- Real endpoint health behavior depends on relay cooldown responses.
