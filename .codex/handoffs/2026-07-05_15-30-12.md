# Task summary

Implemented configurable Custom AI OCR image payload modes. Users can now choose
lossless WebP, balanced lossy WebP, or small grayscale lossy WebP, plus optional
vision detail (`auto`, `low`, `high`). The default is the recommended
`balanced_webp` at quality 85 with detail `auto`.

The API OCR frame cache identity now includes Custom AI OCR image mode, quality,
detail, and keep-linebreaks settings when those settings exist, so the same
frame is not reused across different OCR request payload strategies. Translation
cache, race, and translation request identity were not changed.

# Important decisions

- Added `encode_image_for_api_ocr()` and normalization helpers in `ocr_utils.py`
  to keep image encoding testable and shared.
- Kept `lossless_webp` byte-for-byte equivalent to the previous API OCR WebP
  behavior.
- Defaulted new config to `balanced_webp`, quality `85`, detail `auto`.
- Omitted detail from Chat/Responses payloads when detail is `auto`, preserving
  compatibility for OpenAI-compatible endpoints that do not support explicit
  detail.
- Added `detail` to Chat `image_url` and Responses `input_image` only for
  `low` or `high`.
- Logged encoding mode, encoded byte size, detail, and conversion duration
  without logging base64 image bodies.
- API OCR skips submission if encoding returns no bytes; encoding helper raises
  on empty payloads, and App conversion falls back to lossless WebP before
  returning a clear failure.
