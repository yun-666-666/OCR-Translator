# Windows DWM Target Overlay Border Fix and v3.10.5 Handoff

## Task summary

- Corrected the target-overlay transparency bug that remained after `v3.10.4`.
- Confirmed the residual rounded rectangle was not the Qt stylesheet border.
  Windows 11 DWM was drawing a native outline around the frameless top-level
  PySide window.
- Disabled the DWM native border with `DWMWA_BORDER_COLOR` set to
  `DWMWA_COLOR_NONE`.
- Preserved the application-controlled rounded border at non-zero background
  opacity.
- Prepared the verified local branch for one-way corrective publication as
  `v3.10.5`.

## Root-cause evidence

- The live config contained `target_opacity = 0.0`.
- Runtime logs showed the active source process created the PySide overlay with
  `border_px=1` and `opacity=0.0` after the `v3.10.4` code was loaded.
- Offscreen Qt rendering showed both background and stylesheet border pixels at
  alpha `0`.
- A real Windows desktop A/B capture showed the same rounded outline with both
  `border_px=1` and `border_px=0`, proving the outline was outside Qt
  stylesheet rendering.
- Calling `DwmSetWindowAttribute(..., DWMWA_BORDER_COLOR,
  DWMWA_COLOR_NONE)` removed the outline in the real desktop capture.
- A final capture using the updated `PySideTranslationOverlay` class with
  `opacity=0.0`, `border_px=1`, and visible red text showed the text without
  any rounded frame.

## Important decisions

- The DWM outline is disabled for the frameless target overlay at every opacity,
  rather than only at opacity zero. This prevents the system border from
  competing with the application-controlled rounded border.
- Failure to call the Windows 11 attribute is logged and leaves the prior
  behavior intact, preserving compatibility with older Windows versions.
- The local branch remains the sole source of truth. No pull, merge, rebase, or
  remote checkout is part of the corrective publication.
- The existing ignored `v3.10.3` and `v3.10.4` release-note files remain
  untracked and excluded.
