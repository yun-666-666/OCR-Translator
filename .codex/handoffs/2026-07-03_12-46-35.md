# SQLite cache persistence optimization handoff

## Task summary

Completed a medium/large optimization pass by upgrading `UnifiedTranslationCache` persistence from JSON whole-file snapshots to a SQLite-backed incremental store.

This pass keeps the existing in-memory cache API and key-isolation behavior, but changes persistence to:

- write SQLite databases instead of JSON cache files
- batch ordinary `store()` writes behind the existing delayed timer
- persist provider clears and full clears without rebuilding a JSON file
- migrate a legacy schema-versioned `custom_ai_translation_cache.json` into SQLite on startup

The app default runtime cache path now points to `custom_ai_translation_cache.sqlite3`, and `.gitignore` was updated so the new runtime cache files stay local.

## Important decisions

- Kept `UnifiedTranslationCache` as the public in-memory façade instead of replacing it with direct DB access from handlers.
- Used SQLite row storage with the existing five-part cache key as the persisted primary key.
- Preserved delayed/coalesced persistence for ordinary `store()` calls instead of regressing to synchronous row writes on every translation.
- Kept `clear_provider()` and `clear_all()` as immediate persistence operations.
- Migrated only schema-versioned legacy JSON payloads; invalid legacy JSON is still ignored safely.
- Updated the production runtime cache filename to `.sqlite3` and ignored both the DB and `.tmp` companion file in Git.
- Left `.codex/release-artifacts/` untouched and untracked.
