# Relay GPT-5.6 Model Switch And Live Verification

## Task summary

At the user's request, tested the relay's two lower-cost GPT-5.6 variants and replaced the relay profile's existing `gpt-5.4` model with the successful variant.

The relay model endpoint currently exposes three GPT-5.6 names:

- `gpt-5.6-luna`
- `gpt-5.6-sol`
- `gpt-5.6-terra`

The endpoint does not publish price or tier metadata. Following the user's reference to the two cheaper variants, this increment tested `luna` and `sol` and left `terra` out of the comparison.

## Live test results

Both tests used an in-memory copy of the existing relay profile first, so a failed model could not leave the persisted application configuration broken.

- `gpt-5.6-luna`
  - relay returned HTTP 502 in about 1.1 seconds;
  - the new request-scoped cooldown correctly identified `model=gpt-5.6-luna`;
  - this failure did not block the following `sol` request.
- `gpt-5.6-sol`
  - relay returned HTTP 200 and parsed successfully in about 7.1 seconds;
  - result: `最新的模型测试已成功完成。`;
  - reported usage: 4,587 input tokens and 40 output tokens.

Because `sol` succeeded and `luna` did not, the relay profile was changed from `gpt-5.4` to `gpt-5.6-sol`.

After writing the configuration, a new `CustomAIProfileManager` reloaded it from disk and a fresh real request was sent through that reloaded profile:

- reloaded model: `gpt-5.6-sol`;
- credential reference resolved successfully;
- relay returned HTTP 200 in about 7.7 seconds;
- result: `持久化的 GPT 5.6 模型工作正常。`;
- reported usage: 4,591 input tokens and 72 output tokens.

No credentials, request bodies, or response bodies were printed during the probes.
