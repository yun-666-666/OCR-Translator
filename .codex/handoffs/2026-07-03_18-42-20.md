# Structured Translation I/O Contract Handoff

## Task summary

Completed a fourth large translation-quality optimization.

Translation prompts now send the user message as compact JSON with explicit:

- `previous_approved_translations`;
- `current_source`.

The system message defines those fields as data, makes history context-only, and
instructs the model to translate only `current_source`. Quotes, newlines,
label-like content, and instruction-like source subtitles are therefore escaped
and remain inside an unambiguous data field. Compact separators also remove
repeated `Source:` / `Translation:` prompt tokens.

Successful translation responses now pass through a conservative contract
before reaching the handler, cache, or final display:

- BOM and surrounding whitespace are removed;
- one complete Markdown fence is unwrapped unless the source itself is fenced;
- standalone wrapper lines such as `Translation:` / `译文：` are removed only
  when real content follows;
- a small fixed set of explanatory preambles is removed;
- wrapper-only / empty results raise an error and cannot be cached.

Inline `Translation: unavailable`, dialogue quotes, fenced source code, and a
source that itself begins with a standalone translation label are preserved.
The same final contract applies to Chat Completions, Responses, and streaming
translation results, but not OCR or connection tests.

## Important decisions

- Used JSON rather than custom XML-like delimiters so embedded quotes,
  newlines, field names, and instruction text are escaped deterministically.
- Kept user custom instructions in the system policy and treated OCR source text
  strictly as data.
- Chose deterministic wrapper cleanup instead of a second model call, so normal
  latency and API cost do not increase.
- Did not heuristically remove trailing commentary, language-detect outputs, or
  reject source-identical names; those approaches carry unacceptable false
  positive risk.
- Precomputed wrapper label/preamble constants at module scope rather than
  allocating them on every translation.
- `.codex/release-artifacts/` remains untouched and excluded.

## Remaining issues or next steps

- A streaming UI callback may briefly show a raw prefix before the normalized
  final result replaces it; suppressing partial wrappers safely requires a
  stream-aware prefix buffer.
- Future large work can add adaptive endpoint health scoring or a conservative
  stream-prefix buffer.
