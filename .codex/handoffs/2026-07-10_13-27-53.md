# Settings Wheel and Model Cooldown Isolation

## Task summary

Completed the first large optimization increment requested on 2026-07-10:

1. Settings-tab wheel events over comboboxes, spinboxes, entries, and scales now
   scroll the owning page without changing the hovered control value.
2. Custom AI cooldown now distinguishes credential-wide rate limits from
   model/wire-specific gateway and capacity failures.
3. Cooldown logs now identify `scope=transport` or `scope=request` and the
   selected model without logging credentials.

## Root-cause evidence

### Settings wheel

`create_scrollable_tab` used `bind_all("<MouseWheel>", ...)`. Tk processes the
hovered widget binding and its ttk class binding before the global `all`
binding, so `TCombobox` and `TSpinbox` values changed before the page scrolled.

### GPT relay session

The latest application session did not show three independently parsed GPT
failures:

- At 13:05:59 the first real relay `/responses` translation request returned
  HTTP 502 and activated a 60-second cooldown.
- During the cooldown, 42 translation candidates were queued without another
  model request.
- At 13:07:00 the second real relay request returned HTTP 502 and activated a
  120-second cooldown.
- The model-list endpoint had returned HTTP 200, so discovery was healthy while
  the translation upstream was unavailable.
- After switching to the independent xAI profile, requests returned HTTP 200
  and the parse/display chain worked from 13:09:04 onward.

The previous endpoint-plus-credential cooldown identity made model changes on
the same relay inherit the old failure state. The new split keeps explicit 429
and recognized quota/rate-limit failures credential-wide, while gateway,
capacity, and availability failures use endpoint, credential, wire API, and
model identity.

## Important decisions

- The shared scrollable-tab builder owns the descendant input guard, but the
  Settings tab is the only caller that opts in. Debug and custom-prompt text
  scrolling are unchanged.
- Guarded wheel events run at widget binding priority, scroll the canvas, and
  return `break` before ttk class behavior. Click, keyboard, arrow-button, and
  opened dropdown-list interaction remain available.
- Explicit HTTP 429 and recognized quota/rate-limit errors remain scoped to
  endpoint plus credential. Switching model cannot bypass a real account-wide
  rate limit.
- Other cooldown-triggering upstream availability failures are request scoped
  by normalized wire API and model. GPT-5.6, GPT-5.5, and GPT-5.4 can therefore
  each receive one bounded probe instead of inheriting another model's gateway
  failure.
- No live or paid API call was sent during implementation. Runtime conclusions
  came from the user's existing logs; transport behavior was verified with
  deterministic unit tests.
