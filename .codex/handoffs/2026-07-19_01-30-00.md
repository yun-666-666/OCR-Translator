# P16: Missing usage must not look like zero tokens

## Task summary

Provider stream/response paths without usage now report `usage_missing` / `n/a` in short logs and keep unknown values out of zero-cost / zero-token metrics. Explicit zero usage still formats as `0`.

## Changes

### `custom_ai_requests.py`
- `_extract_usage` returns `{usage_missing: True}` when usage is absent/empty
- Numeric fields are included only when present; explicit zeros preserved
- No invented `0` token or `$0` cost for missing usage

### `handlers/translation_context.py`
- Optional usage number helpers distinguish missing vs zero
- Cache-ratio metrics skip unknown usage so averages are not polluted by zeros

### `handlers/translation_results.py`
- Short-log formats unknown counts/cost as `n/a` and marks `usage_missing`
- Default short log remains content-free (O1)

### Tests
- Missing usage extraction + short-log `n/a`
- Explicit zero still numeric
- Stream-without-usage expects `usage_missing`
