# Task summary

Completed big optimization #12: streamed translation truncation detection and
automatic repair.

The Chat Completions stream parser now preserves terminal `finish_reason`, and
the Responses stream parser now preserves `status`, `incomplete_details`, and
usage from `response.completed` / `response.incomplete`. The latter also infers
`status: incomplete` for compatible relays that omit it from the embedded
response.

This lets the existing quality recovery path recognize explicitly truncated
streamed translations, retry once without the output-token limit, and return
the complete second result instead of caching a partial translation.

# Important decisions

- Verified the terminal event formats against the current official OpenAI API
  references before implementation.
- Reused the existing one-retry quality repair instead of adding another retry
  mechanism.
- Preserved normal streaming callbacks; a user can still see the first partial
  promptly while the final returned/cached result is repaired.
- Kept compatibility with relays that omit terminal metadata: their current
  successful behavior is unchanged.
- Added inference only for an explicit `response.incomplete` event, avoiding
  guesses based on translation length.
- Left the pre-existing untracked `.codex/release-artifacts/` untouched.
