# O8 review repair: keep adaptive snapshot refresh on the UI thread

## Task summary

Reviewed Grok's O8 capture snapshot implementation and found a real thread-boundary regression: `run_capture_thread()` still called `app.update_adaptive_scan_interval()`. The real method reads Tk variables and republishes snapshots, so the worker could still invoke Tk APIs despite the immutable snapshot design.

Moved adaptive interval refresh to a UI-owned periodic callback that publishes the next immutable snapshot. The capture worker now only consumes a previously published snapshot and waits safely when none exists.

## Important decisions

- The worker calls `get_capture_ui_snapshot(..., allow_unpublished_build=False)` and never builds a fallback snapshot from the app, preventing accidental Tk reads before UI publication.
- UI lifecycle start begins a 500 ms adaptive refresh; normal Stop and app-close cancel it.
- Local OCR adaptive pacing remains active because `update_adaptive_scan_interval()` still runs periodically, but only on the UI thread.
- Existing latest-only queue and generation invalidation behavior remain unchanged.
