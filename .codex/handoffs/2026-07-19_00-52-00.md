# O9 review repair: transient failure coverage and stale provider isolation

## Task summary

Reviewed Grok's O9 implementation for throttled, non-intrusive transient translation-failure status. The UI update path and threshold/status behavior were sound, but two failures prevented the promised safety and observability guarantees:

- The existing transient predicate did not recognize the 502/503/504 and offline/connection forms already classified as temporary by the Custom AI failover layer. Those responses still replaced the subtitle with an error instead of participating in O9's silent, throttled status path.
- A response from an older in-flight request could be attributed to the currently selected provider after a provider switch, because failure visibility only compared against the last displayed sequence.

The repair extends the predicate only to strict, recoverable provider failure forms and makes O9 state updates ignore a sequence older than the newest submitted translation.

## Important decisions

- The 429/credential/permanent-error behavior is unchanged; the predicate only adopts strict 5xx/network/unavailable markers already treated as temporary by the failover classification.
- The existing subtitle ordering behavior is not changed. The new sequence guard applies only to O9's failure-visibility state, so a late old reply cannot clear or increment the active provider's status state.
- The pre-existing untracked Grok O9 handoff and unrelated untracked workspace files were preserved and excluded from this repair.

## Remaining notes

- O9 is now consistent with its stated fixed-5xx/offline acceptance scenario: old subtitle stays visible, a single failure is silent, and repeated failures surface only through the throttled status label.
