# Important decisions

- Accepted Grok 4.5 recommendation B: stop only at provider boundaries when a newer sequence has started.
- Did not cancel an HTTP request already in progress.
- Did not change cache retention, timeouts, profile ordering, or user configuration.
- Historical 4.5 latency supports keeping real-time OCR local and translation non-reasoning, but it does not justify a scheduler rewrite.
- Rejected cooperative cancellation, giant-module splitting, and broad refactoring because the logs do not justify their risk.
- The strict comparison `request_sequence < latest_translation_sequence_started` is intentional; `<=` would make the current request obsolete itself.
