# Task summary

Optimized Custom AI translation requests for prompt caching and adaptive
context control.

The translation payload now keeps fixed system rules stable whether previous
context is present or absent, places the user custom prompt in a stable system
message before per-request JSON, and leaves `previous_approved_translations`
before `current_source` in the final user message so changing source text stays
late in the request.

Usage extraction now exposes input/output token aliases, cached input token
aliases, and `cached_input_ratio`. Translation short logs include a compact
`cached_input_ratio=...` metric. The translation handler keeps a lightweight EMA
of recent cached ratio/input-token observations and conservatively shrinks the
previous-context character budget only after enough low-cache or very-long-input
samples.

# Important decisions

- Kept the cache identity content-based: selected request context still enters
  cache params and in-flight keys, and no extra policy setting was introduced.
- Did not add UI/config switches; the conservative adaptive behavior is default
  and only changes context size after several usage samples.
- Kept structured output schema handling unchanged; layout changes only affect
  message order/content before the existing schema payload is attached.
- Kept stream/race request snapshots intact. Race candidates still receive the
  same context snapshot, and token statistics are recorded after a provider
  response without touching partial streaming display.
- OCR usage can be logged with a ratio, but only translation usage updates the
  adaptive context-budget state.
