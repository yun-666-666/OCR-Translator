# DisplayManager translation schedule uses close-aware guards

## Candidate selection

Selected the single confirmed DisplayManager close-race from the readonly review.

Problem:
`DisplayManager.update_translation_text()` checked overlay/widget existence, then called raw `root.after(0, ...)` without handling:
- `_app_is_closing`
- `is_running=False`
- missing/destroyed root
- `winfo_exists()` TclError during teardown
- `root.after()` RuntimeError / TclError

Scope kept strictly to this schedule path only.

User WIP deliberately left untouched:
- `gui_settings_builder.py`
- `modern_ui.py`
- `tests/test_modern_ui.py`

## Task summary

`update_translation_text` now:
1. returns early when the app is closing or not running;
2. returns when root is missing or reports not existing;
3. still validates target overlay / translation widget existence;
4. schedules the same healthy-path callback:
   `root.after(0, self._update_translation_text_on_main_thread, text_to_display)`;
5. swallows `RuntimeError` / `tk.TclError` so teardown never raises from this path.

No import of `worker_translation._schedule_ui_callback` (avoids reverse dependency).
