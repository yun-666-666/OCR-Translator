# P1: short secret-field redaction in centralized sanitizer

## Candidate selection

Follow-up to `992235b` (diagnostic log sanitization and coalescing).

Reproduced gap: `sanitize_log_message()` redacted URL query secrets, Bearer
tokens, and long opaque tokens, but missed ordinary short key/value forms such
as `api_key=short`, `token=ab`, `password=cd`, `secret=ef`, plus JSON / header
equivalents.

Scope limited to:

- `logger.py`
- `tests/test_runtime_logging.py`
- this handoff

User WIP left untouched:

- `gui_settings_builder.py`
- `modern_ui.py`
- `tests/test_modern_ui.py`

No worker / request / cache / retry / timeout / UI changes.

## Task summary

1. Replaced URL-only / header-only secret assignment regexes with a single
   `_SECRET_FIELD_ASSIGNMENT_RE` covering:
   - plain `field=value` / `field: value`
   - URL query forms
   - JSON-ish `"field":"value"`
   - header-like `x-api-key: …`, `x-auth-token: …`, `api-key: …`
2. Sensitive field allow-list only:
   `api_key`, `api-key`, `access_token`, `access-token`, `token`, `secret`,
   `password`, `authorization`, `x-api-key`, `x-auth-token`.
3. Field name + separator preserved; value replaced with `[redacted]`.
4. Non-identifier left boundary (`(?<![A-Za-z0-9_])`) so
   `INVALID_API_KEY: Invalid API key` is **not** treated as `api_key=…`.
5. Ordinary diagnostics preserved:
   `status=timeout`, `class=transport`, `duration_ms=123`, etc.
6. Parameterized unit tests for short/long/query/Bearer/JSON/header forms, plus
   file-write assertion that short sentinels never reach `translator_debug.log`.

## Conscious exception (not changed)

Custom AI short-log **opt-in content logging**
(`custom_ai_log_content_enabled` / `_is_custom_ai_log_content_enabled`) still
writes result bodies when the user explicitly enables that privacy option.
That path is intentional, gated, and tied to GUI settings currently in user
WIP. This patch does **not** alter short-log body policy.
