# Large runtime module split handoff

## Task summary

Split the five largest runtime Python modules into focused modules while
preserving the established public import paths, class names, UI, configuration,
provider behavior, and worker behavior. Each target was verified independently
with automated tests and a real application launch controlled through Windows
UI automation before work proceeded to the next target.

No paid provider request was made.

- `gui_builder.py`: 2359 -> 435 lines
- `app_logic.py`: 2737 -> 866 lines
- `handlers/translation_handler.py`: 2497 -> 178 lines
- `worker_threads.py`: 2830 -> 886 lines
- `custom_ai.py`: 3901 -> 146 lines

The original modules remain compatibility facades. Existing callers continue
to import the same public names.

## TDD and compatibility evidence

Seven structural tests were added. Each target first failed because its focused
module did not yet exist, then passed after extraction. Additional dependency
tests recursively inspect nested GUI builder scopes so moved callbacks cannot
silently retain unresolved globals.

Compatibility seams explicitly preserved include:

- `gui_builder.threading.Thread` and `gui_builder.messagebox`
- `app_logic.log_debug`, `app_logic.time`, and PaddleOCR factories
- `handlers.translation_handler.append_rotating_text` and
  `log_debug_coalesced`, including alternate importlib-loaded test modules
- `worker_threads.start_async_translation`, capture functions, timing modules,
  and PaddleOCR recognition functions
- `custom_ai.create_default_credential_store`, `custom_ai.log_debug`, and
  `custom_ai.time`

## Real application verification after each target

1. `gui_builder.py`: launched the real application; opened Home, Settings,
   Custom Prompt, and Debug. The first launches exposed two missing nested
   dependencies, both received regression tests and fixes. Relaunch passed and
   closed normally.
2. `app_logic.py`: launched, switched tabs, exercised source/target visibility
   lifecycle shortcuts, remained responsive, and closed normally.
3. `handlers/translation_handler.py`: launched, inspected live translation
   profile settings and performance diagnostics without submitting a provider
   request, and closed normally.
4. `worker_threads.py`: launched and observed the real PaddleOCR startup prewarm
   complete successfully in 7.27 seconds; inspected diagnostics and closed.
   After the final capture-thread extraction, launched and closed again with no
   remaining Python application window.
5. `custom_ai.py`: launched, opened Settings, opened the live Custom AI profile
   selector, dismissed it without changing or saving data, and closed normally.

## Important decisions

- Used compatibility facades and focused mixins/helpers instead of converting
  same-named modules into packages.
- Preserved module-level monkeypatch and runtime substitution behavior rather
  than binding dependencies early in the new modules.
- Kept tests in their existing large files as requested; only structural and
  source-location assertions were added or updated.
- Did not redesign the UI, add features, change settings, call paid APIs,
  commit, push, tag, or publish.

## Remaining issues or next steps

- Some focused implementation modules remain around 1000-1400 lines because

- Existing unrelated untracked files and the pre-existing route-adaptive
