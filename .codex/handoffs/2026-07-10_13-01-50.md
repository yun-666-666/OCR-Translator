# Cooldown Queue and Gateway Error Optimization

## Task summary

Analyzed the latest 2026-07-10 application session and implemented the three
remaining evidence-backed optimizations:

1. Exact duplicate pending translation requests are coalesced before another
   translation-cache lookup.
2. Late failures from concurrently in-flight requests share one provider
   cooldown backoff step.
3. Upstream HTML error pages are reduced to a short title or generic summary
   before reaching logs or the subtitle overlay.

## Important decisions

- Pending requests coalesce only when the source text is exactly equal and a
  pending flush timer is actually scheduled. An orphaned pending dictionary
  re-enters the normal cache and queue path instead of becoming stranded.
- Coalescing updates only the newest OCR sequence. It preserves the original
  request timestamp, deadline, timer generation, and latest-wins behavior.
- An already active cooldown may be extended by a later `Retry-After`, but the
  backoff counter does not grow. A failure after cooldown expiry still advances
  the bounded exponential backoff.
- HTML detection uses `Content-Type` or leading markup. The standard-library
  HTML parser extracts and normalizes the title; body markup is never returned.
- JSON and plain-text API error handling is unchanged.
