# Handoff — Subtitle fast-path content-free diagnostics (2026-07-23)

## Task summary

Added **content-free, aggregated diagnostics** for PaddleOCR subtitle fast-path fallback reasons.
**No crop threshold, min_score, model/device/region/UI, or full-OCR fallback behavior was changed.**

Motivation:
- Live logs still show many `no line crop` / `no usable text` outcomes.
- Without classification, it is impossible to safely decide whether the dominant cause is empty frames, fullwidth-short reject, edge miss, low-confidence recognition, or noise filtering.
- Prior threshold experiments were withdrawn for lack of sample proof; this task only instruments.

## What was added

### Counters
`get_subtitle_fastpath_diagnostics_snapshot()` / `reset_subtitle_fastpath_diagnostics()`

Examples:
- `bright_mask_empty`
- `bright_crop_success` / `bright_no_crop`
- `bright_reject_fullwidth_short` (+ width/height ratio buckets)
- `bright_reject_tiny|tall_block|huge_block|large_area`
- `edge_fallback_attempted|edge_fallback_crop_success|edge_fallback_no_crop`
- `edge_reject_*`
- `no_crop_reason_bright_*` / `no_crop_reason_edge_*`
- `rec_low_confidence|rec_noise|rec_empty|rec_kept`
- `fast_path_success|fast_path_no_usable_text|fast_path_error|fast_path_no_line_crop`
- `full_fallback_text|full_fallback_empty|full_fallback_error`

### Coalesced logs
Existing event keys remain, with a short content-free suffix, e.g.:

```text
PaddleOCR subtitle fast path found no line crop; falling back to full OCR [outcome=fast_path_no_line_crop reason=no_crop_reason_bright_reject_fullwidth_short_wge80_h10_14]
PaddleOCR full OCR fallback produced text lines=1 chars=12 [outcome=full_fallback_text]
```

No OCR text body, pixels, paths, or absolute coordinates are logged.
Full bucket detail is only in the counter snapshot API.

## Exact branch mapping

| Classification | Code branch |
|---|---|
| bright mask empty | `prepare_...` when `not bright_mask.any()` |
| bright reject fullwidth short | `_extract_...` rule `width>0.90 and height<0.14` |
| bright reject tiny/tall/huge/large_area | same component filters |
| edge fallback attempted/success/no crop | after bright fails or empty |
| no crop reason bright/edge | top reject reason promotion when crops empty |
| fast recognition low-conf/noise/empty/kept | `flatten_paddleocr_text_recognition_result` |
| fast path success / no usable text / error / no line crop | `recognize_subtitle_with_paddleocr` |
| full fallback text/empty/error | after fallback to `recognize_with_paddleocr` |

- `min_score` unchanged
- noise filter unchanged
- full OCR fallback still always used on fast-path failure

## How to use next live logs
1. Grep:
   - `found no line crop`
   - `found no usable text`
   - `full OCR fallback produced`
   - `outcome=` / `reason=`
2. Count dominant `reason=` values for no-crop.
3. Compare:
   - if mostly `reject_fullwidth_short` → only then consider crop-threshold experiments
   - if mostly empty/no candidates → content/region issue, not filter bug
   - if crop succeeds but `rec_low_confidence`/`noise` dominate → recognition/filter issue, not crop
   - if full fallback empty too → source frame often truly empty
