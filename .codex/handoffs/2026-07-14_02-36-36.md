## Important decisions

- The runner uses `sys.executable` and argument lists only; each child process gets one disposable log directory rather than the caller's runtime directory.
- The focused subprocess tests use a temporary miniature project to prove both commands actually run, a failed first command prevents the second command, and the caller log directory is unchanged.
- No package, provider, secret, or real network operation is invoked by the runner or workflow definition.
- `actions/checkout@v4` explicitly sets `persist-credentials: false`, preventing the checkout token from being retained in local Git configuration during offline-test steps.
- Workflow permissions are explicitly limited to `contents: read`; requirement installation and test execution receive no broader default `GITHUB_TOKEN` capability.
