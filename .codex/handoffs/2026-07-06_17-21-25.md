# Task summary

Rechecked the latest GUI application logs after the user reported continued
Custom AI translation errors and fast subtitles still being missed. The user
requested two parallel agents, so two read-only explorer agents were spawned:

- Agent A investigated Custom AI/xAI translation errors.
- Agent B investigated PaddleOCR fast-subtitle recognition misses.

Latest log findings from the 2026-07-06 16:59:35-17:02:05 run:

- PaddleOCR still routed correctly through the offline PP-OCRv6 path.
- 754 locally parsed OCR duration samples averaged about 0.118s, p50 0.094s,
  p90 0.234s, max 0.438s.
- Full OCR fallback was still frequent: 219 fallback lines in the local count;
  the OCR explorer counted 260 fallback events across the full rotated log span.
- Translation latency was a separate pressure point: 66 translation timing
  samples averaged about 2.788s total latency, p90 5.953s, max 11.219s.
- No evidence of HTTP 429 or provider rate-limit cooldowns appeared in the
  latest run. xAI stream calls logged status 200.
- Visible Custom AI errors came from transient stream/network failures:
  empty stream message content, read timeout, and connection reset.
- Fast OCR misses were mostly truncated/noisy candidates such as `NMMNm`,
  `If I'm going to lis`, `ing to live`, and `Carter Beauford is the bes`.

Root causes addressed in this pass:

- xAI stream mode can return HTTP 200 without message content, or fail mid-stream.
  The app treated that as a normal translation result string and displayed it
  over the subtitle area.
- The OCR stability gate treated some truncated PaddleOCR fragments as clear
  enough to submit immediately, especially short vowel-less single tokens and
  multi-token strings ending in a likely cut-off 3-letter tail.

Implemented fixes:

- Custom AI stream translation now retries once through the non-stream request
  path for transient stream failures before surfacing an error.
- Transient Custom AI provider errors are suppressed at display time so they do
  not cover the current subtitle if fallback also fails.
- The OCR stability gate now treats short vowel-less single-token OCR output and
  likely truncated 3-letter tail fragments as low-quality candidates, giving a
  more complete subtitle a short window to replace them.
