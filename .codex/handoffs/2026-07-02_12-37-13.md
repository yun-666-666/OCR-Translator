## Important decisions made

- Kept the existing latest-request-wins behavior; no queue of obsolete subtitle text was introduced.
- Added a monotonic deadline plus generation token instead of cancelling Tk timers from a worker thread.
- Superseded timers remain harmless no-ops when they eventually fire.
- Translation completion expedites the latest pending request through the normal scheduler, so cooldown, submit interval, and concurrency checks still remain authoritative.
- Kept Custom AI concurrency at one.
- Implemented per-base-URL exponential cooldown backoff with a 300-second cap.
- A successful provider response resets only the consecutive-failure counter. It does not prematurely erase an active cooldown deadline that may have been set by another request.
- Did not broaden OCR fuzzy matching because the current near-duplicate logic is already conservative and further relaxation risks suppressing meaningful text changes.

## Known issues or follow-up work

- This directory has no `.git` metadata, so no branch, commit, merge, or PR operation was possible.
- The desktop smoke test covered startup/render/shutdown only. It did not start live screen OCR because doing so would capture unrelated on-screen content.
- Tk timers that are superseded are deliberately not cancelled from worker threads; they wake later and exit on the generation check. This avoids cross-thread `after_cancel` risk at the cost of a small number of no-op callbacks.
- Adaptive RTT-based pacing remains a possible later optimization, but the completion wakeup removes the clearest avoidable delay without changing provider semantics.
