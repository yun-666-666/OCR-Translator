# Task summary

Completed big optimization #11: automatic recovery for transient persistent
translation-cache write failures.

Failed SQLite writes now preserve dirty state and request a retry through the
existing single background timer. Consecutive failures use capped exponential
backoff (`1, 2, 4, 8, 16, 30, 30...` seconds), while any successful write
resets the backoff. Explicit flushes and cache-clear persistence use the same
recovery path. Shutdown remains synchronous and never leaves a retry timer.

# Important decisions

- Reused one timer instead of creating a separate retry worker.
- Kept normal write coalescing delay separate from recovery backoff.
- Capped recovery at 30 seconds to avoid both busy loops and very long silent
  periods.
- Centralized persistence result handling so scheduled writes, explicit
  flushes, post-close stores, and clear operations share consistent state.
- A concurrently scheduled normal timer wins over creating a duplicate retry
  timer and still carries all retained dirty state.
- Marked the cache closed before its final flush, preventing background work
  after shutdown.
- Left the pre-existing untracked `.codex/release-artifacts/` untouched.
