# Task summary

Completed big optimization #10: persistent translation-cache access recency.
Cache hits now update SQLite recency through the existing delayed delta writer
at most once per key per 60 seconds. Closing the cache batches any newer
unqueued hit timestamps into the final flush. This keeps frequently reused
translations from being incorrectly evicted after restart without adding a
database write to every cache hit.

# Important decisions

- Reused the existing delayed, coalesced SQLite delta writer so cache hits stay
  non-blocking.
- Used a per-key 60-second persistence-request interval to bound write churn.
- Seeded request timestamps from stored access times so restart does not cause
  an immediate write for every first hit.
- Added a close-time batch to preserve hits inside the throttle window.
- Kept in-memory-only caches free of persistence generations on close.
- Left the pre-existing untracked `.codex/release-artifacts/` untouched.
