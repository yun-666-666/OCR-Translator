# Large Translation Pipeline Optimization Handoff

## Task summary

Completed one large, integrated optimization batch aimed at faster and more
reliable Custom AI translation:

- restored immediate repeated-subtitle cache hits while preserving useful
  history context;
- refreshed duplicate context entries and capped request context at 4000
  characters;
- coalesced streaming UI callbacks and skipped duplicate final rendering;
- bounded non-reasoning translation output, omitted limits for reasoning
  profiles, and strengthened the source-as-data instruction;
- stopped deterministic endpoint failures from probing equivalent fallback
  URLs;
- learned providers that reject output-limit fields and retried once without
  the unsupported field;
- retried explicitly truncated translation responses without an output limit;
- unified handler/worker translation error classification so failures do not
  enter caches or success state;
- recorded cached prompt tokens in short logs;
- moved Custom AI short-log disk writes off the translation/OCR return path
  while keeping an ordered close-time flush barrier.

## Important decisions

- Output limits are optimization hints, not correctness boundaries. Explicitly
  truncated responses are retried without the limit.
- Provider output-limit incompatibility is remembered per wire API, normalized
  base URL, and model for the current process.
- Only deterministic failures stop equivalent URL fallback; endpoint-shape
  discovery failures can still try alternatives.
- Context cache keys exclude the current source so repeated subtitles hit the
  cache, but older source/translation pairs remain part of semantic identity.
- Short-log writes use one private worker to preserve order. Close detaches the
  worker under a lock and waits outside the lock, preventing both submission
  races and shutdown deadlocks.
- `.codex/release-artifacts/` was pre-existing and remains intentionally
  untouched and excluded from this batch.
