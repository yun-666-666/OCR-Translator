## Task summary

- Replaced the separate Custom AI response mode, OCR image format, image mode,
  image quality, and image detail settings with one `ai_optimization_mode`
  selector: `auto`, `speed`, or `quality`.

  default, with bounded racing only after enough route-scoped evidence and at
  least two healthy alternatives.

  defaults.

  `Translate naturally and concisely. Preserve meaning, tone, names, and terminology; use context only when needed.`
- Put translated-subtitle bold and horizontal-center controls on one row.
- Put source-area, target-area, and target-text colors on one row; removed the

## Important decisions

- MSS was selected as the only screenshot backend because the current logs
  showed better aggregate/tail behavior and PaddleOCR consumes the resulting
  pixels rather than depending on the capture library.
- Automatic response mode never chooses streaming from latency alone.
- Route latency is recorded under a hash-scoped API OCR metric so one
  profile/relay cannot affect another profile's image policy.
- Thin, wide, or large screenshots keep high image detail even on a slow
  route; only compact non-thin images are downgraded for a persistently slow
  route.
- The OCR cache key and actual encoder reuse the same resolved image decision.
- Explicit provider messages such as “Only JPEG and PNG images are supported”
  teach the route capability memory without learning from unrelated failures.
- MSS error details are bounded and sanitized before logging.
