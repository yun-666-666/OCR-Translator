# Task summary

Completed big optimization #15: thread-safe, sequence-aware translation
context.

Concurrent provider requests may finish out of order when the scheduler opens
its bounded overflow slot. Approved Custom AI context is now ordered by the
existing translation request sequence instead of network completion time.
Reads, clears, and updates are protected by a reentrant lock.

Late older results are inserted chronologically and trimmed as old context.
They cannot displace newer entries in a small window or overwrite a newer
translation for the same source. Instant cache hits infer the next display
sequence from the app counter.

# Important decisions

- Preserved the public `(source, translation)` list shape; ordering metadata is
  internal only.
- Reused the scheduler's existing `translation_sequence` rather than creating a
  second clock for provider results.
- Used a monotonic fallback order for direct callers without a sequence.
- Synchronized metadata for tests or integrations that directly assign the
  public context window.
- Snapshot context under the lock before applying the adaptive character
  budget, keeping provider payload construction free of a long-held lock.
- Dropped only an explicitly older result for the same source; distinct older
  subtitles are retained if they still fit the configured window.
- Left the pre-existing untracked `.codex/release-artifacts/` untouched.
