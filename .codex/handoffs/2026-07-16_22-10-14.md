# Important decisions

- `auto` remains adaptive; `stream` is explicit; `speed` uses stream plus a frozen no-reasoning request policy; `quality` remains safe non-streaming.
- The speed policy is stored in each request snapshot and propagated to failover/race candidates, so live UI changes cannot alter an in-flight request.
- One recent route error blocks adaptive streaming until a successful request resets the error state.
- During PaddleOCR setting invalidation, an active prewarm keeps ownership of its original completion event. New work waits for that operation for at most 20 seconds instead of starting another heavyweight initialization.
- Trace-driven saves are coalesced for 400 ms. Actual writes always bypass the older handler-level 100 ms debounce, including explicit saves and shutdown.
- Worker UI dispatch only suppresses expected Tk shutdown errors (`RuntimeError` and `TclError`); unrelated programming errors remain visible.
