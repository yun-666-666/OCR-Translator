# Stale Translation Head-of-Line Bypass Handoff

## Task summary

Completed and verified a second large translation-latency optimization.

Previously, Custom AI translation allowed one active logical request. When that
request became slow and OCR advanced to a new subtitle, the newest subtitle
waited for the obsolete request's full network duration even though sequence
ordering would later reject the obsolete display.

The scheduler now:

- records the monotonic start time for each active translation;
- keeps normal Custom AI concurrency at one;
- lets the newest subtitle use one overflow slot after the sole active request
  is 1.5 seconds old;
- never permits more than two logical translation requests;
- queues younger requests directly to the exact supersede deadline;
- continues retaining only the newest pending subtitle;
- preserves duplicate in-flight suppression, cooldowns, submit intervals, and
  chronological display protection;
- disables outer supersession in `race` mode because one race request already
  fans out to multiple same-model profiles;
- removes timing state on both submit rollback and worker completion.

## Important decisions

- Chose a 1.5-second threshold: high enough to avoid overlapping ordinary fast
  calls, but well below the multi-second median observed in historical real
  profile short logs.
- Kept a strict two-request hard cap so rapid OCR changes cannot create an
  unbounded request fan-out.
- Did not cancel obsolete `requests` calls because synchronous HTTP cancellation
  is not safely available here. Their results remain cacheable and display
  ordering already rejects stale UI updates.
- Cooldown and submit-interval gates still win over supersession.
- `race` mode stays at its existing outer concurrency because it has its own
  endpoint-level parallelism.
- `.codex/release-artifacts/` remains untouched and excluded.

## Remaining issues or next steps

- Real-network gains depend on the selected relay latency distribution; the
  deterministic scheduler tests prove the wait is removed after the threshold.
- Future large optimization work can add latency-history-based endpoint
  selection or quality-aware translation-memory fallback.
