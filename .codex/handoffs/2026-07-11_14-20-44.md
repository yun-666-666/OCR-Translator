## Major optimization 1: route-scoped Custom AI adaptation

- Replaced the single global adaptive latency advisor and prompt-cache EMA with
  bounded per-route state.
- Route ownership uses canonical endpoint, a hashed sensitive-URL-options
  identity, credential fingerprint, wire API, and model.
- Raw API keys, URL userinfo, query tokens, and fragments never appear in the
  route-state key.
- Successful, failed, race-winning, and request-snapshot observations remain
  attached to the immutable request route after a live profile change.
- The LRU maps are capped at 32 routes and lookup/mutation is protected from
  concurrent eviction.
- Context budgeting now reads only the active request route's cached-token
  history.

## Major optimization 2: transactional Custom AI profiles

- Profile JSON writes now use a unique sibling temporary file, flush, fsync,
  and atomic `os.replace`.
- Add, update, delete, and active-profile changes save detached staged data;
  live readers continue to see the old committed snapshot until replace
  succeeds.
- Profile readers return complete copies and published data changes by one
  reference replacement, preventing empty or half-updated profile views.
- API-key updates write a versioned credential reference, commit JSON, then
  retire the old reference. A crash at any point leaves either the old or new
  disk configuration with a valid credential.
- Failed adds/updates/deletes preserve the prior in-memory and credential
  state. Deletion commits JSON before best-effort credential cleanup.
- The default atomic-temp family is gitignored, and startup narrowly removes
  only stale temp files belonging to its own profile filename.

## Important decisions

- Do not weaken or bypass relay cooldown behavior to mask `测试3` HTTP 502.
- Keep adaptive and cached-token state isolated by the immutable provider
  route; official prompt-caching guidance treats stable route/key measurement
  as the useful optimization boundary.
- Prefer old-or-new committed profile visibility over in-place mutation.
- Keep credential cleanup after durable JSON commits so cleanup failure can
  only leave an orphan secret, never a broken live configuration.
- Merge the remote branch normally after committing local work; do not rebase a
  mixed worktree.
- Leave unrelated untracked Rust experiments, `SKILL.md`, `log_analysis.txt`,
  and the Rust audit handoff untouched and outside the release commit.
